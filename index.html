01. 왜 하나요?

모든 것을 의심하는 것이
이곳의 규칙이에요.

우리는 왜 SW를 배우나요? 왜 누군가에게 평가받아야 하죠? 오지선다형 밖에 세상은 없나요? 이 강의는 답을 주지 않습니다. 대신 질문을 문서로 옮기는 법을 함께 연습합니다.

시빅해킹(Civic Hacking)은 시민들이 새로운 도구와 접근 방법을 사용하여 신속하고 창의적으로 협업함으로써 그들의 도시 또는 정부 시스템을 개선시켜 나가는 사회운동 출처: 위키백과

2020년에 있었던 일

가짜뉴스에 맞서 정확한 정보를 전하려고 코로나맵이 만들어졌습니다. 자원봉사자 80명, 마스크맵을 포함해 10개 프로젝트, 수백만 명의 방문자.

지금 달라진 것

그때 여러 사람이 며칠 걸려 만들던 화면을, 지금은 혼자서 반나절에 세울 수 있습니다. 만드는 일은 더 이상 병목이 아닙니다.

그래서 오늘의 승부처

남은 병목은 하나 — 무엇을 만들지 정확히 말하는 능력입니다. 오늘 여러분이 직접 쓸 파일은 코드가 아니라 요구사항.md 한 장입니다.

거대한 문샷 씽킹이 아니라, 미노베이션(Mini + innovation)

혁신이 아니라 혁신적 실행력입니다. 사소한 변화들의 축적이 거대한 물결을 만듭니다. 오늘 만들 것은 세상을 바꾸는 플랫폼이 아니라 웹페이지 한 장입니다. 지극히 개인적인 문제여도 괜찮습니다. 그것은 여러분만의 문제가 아니거든요.

만들 것
index.html + pre.html해결책 웹페이지와 3분 발표자료
제출할 것
GitHub Pages URL 하나구글 폼으로 제출 · 링크가 열려야 제출입니다
말할 것
3분불편했던 장면 → 만든 것 → 배운 것

03. 주제 찾기

자, 여러분 주위에는
어떤 문제가 있나요?

관심 있는 분야를 고르고, 그 문제가 누구의 문제인지 범위를 골라보세요. 아래는 정답이 아니라 출발점입니다. 마음에 드는 문장이 있다면 그것을 내 언어로 다시 쓰세요.

1. 어떤 분야가 궁금한가요? (여러 개 선택 가능)

2. 누구의 문제인가요? (선택하면 해당 범위의 주제를 위로 올려드려요)

분야를 하나 이상 골라주세요. 고민된다면 랜덤으로 하나 뽑기도 좋은 방법입니다.

주제가 잘 안 잡힐 때 쓰는 확장 사다리

호기심 · 문제 · 고민을 아래 순서로 넓혀보세요. 어디서 멈춰도 괜찮습니다.

나→ 가족→ 이웃→ 지역→ 국가→ 세계

고른 주제, 오늘 안에 될까요?

세 축으로 점검해봅니다. 점수가 낮다고 나쁜 주제가 아닙니다. 주제를 바꾸기 전에 더 작게 자르는 것을 먼저 고민하세요.

세 축 모두 10점일 필요는 없습니다. 후보 주제를 2~3개 넣고 비교해보면 선택이 훨씬 빨라집니다.

05. AI 활용법

    
AI는 심사위원이 아니라,
가장 부지런한 팀원입니다.

    
그대로 복사해서 쓰고, 여러분의 주제에 맞게 [대괄호] 부분만 바꿔보세요. 답이 마음에 들지 않으면 되묻는 것이 핵심입니다.


    


    

      

        
사실은 직접 확인

        
AI는 그럴듯한 거짓을 말합니다. 통계·법령·기관명은 반드시 원문 출처로 확인하세요.

      

      

        
개인정보 금지

        
실명·연락처·주소는 넣지 마세요. GitHub Pages는 누구나 볼 수 있는 공개 웹입니다.

      

      

        
편향을 의심

        
AI의 답은 다수의 목소리에 가깝습니다. 우리가 돕고 싶은 사람은 대개 소수입니다.

      

      

        
모르는 코드는 남기지 않기

        
발표에서 "이건 AI가 해줬어요"라고 말하게 됩니다. 한 줄씩 물어보며 이해하세요.

08. 자료실

    
배포와 데이터

    
배포는 GitHub Pages 하나로 끝냅니다. 그리고 문제를 주장이 아니라 근거로 말하려면 데이터가 필요합니다.


    

      
GitHub Pages 배포 4단계

      
    
        
  1. GitHub에서 새 저장소(Repository)를 만듭니다. 공개(Public)로 만들어야 합니다.
    2. 
        
  2. 만든 index.html과 pre.html을 저장소에 업로드합니다. (Add file → Upload files)
    3. 
        
  3. 저장소의 Settings → Pages에서 Source를 Deploy from a branch, 브랜치를 main / (root)으로 지정하고 Save.
    4. 
        
  4. 1~2분 뒤 https://아이디.github.io/저장소이름/ 으로 접속해봅니다. 발표자료는 뒤에 pre.html을 붙이면 됩니다.
    5. 
      

      

        ⚠ 파일 이름은 반드시 index.html 이어야 첫 화면으로 열립니다.
        제출 전에 내 휴대폰이나 옆 사람 기기로 링크를 한 번 열어보세요. 안 열리면 없는 프로젝트입니다.

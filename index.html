AI 시대의 시빅해킹 해커톤 · 강의자료

우리는,
시빅해커입니다.

좋은 해결책은 좋은 질문에서 시작합니다.

오늘은 내 주변에서 불편했던 일 하나를 고릅니다. 그걸 요구사항.md 라는 문서 한 장에 적고, AI에게 건네 웹페이지로 만듭니다. 마지막엔 친구에게 보낼 수 있는 진짜 링크가 남습니다.

상 받을 작품이 아니라, 누군가에게 도움이 되는 것을 만듭니다. 등수도, 평가도 없습니다.

01. 왜 하나요?

모든 것을 의심하는 것이
이곳의 규칙이에요.

우리는 왜 코딩을 배울까요? 왜 늘 누군가에게 점수를 받아야 할까요? 정답이 다섯 개 중 하나인 세상이 전부일까요? 오늘은 답을 알려주지 않습니다. 대신 내 머릿속 질문을 글로 옮기는 연습을 함께 합니다.

시빅해킹(Civic Hacking)은 시민들이 새로운 도구와 접근 방법을 사용하여 신속하고 창의적으로 협업함으로써 그들의 도시 또는 정부 시스템을 개선시켜 나가는 사회운동 출처: 위키백과

쉽게 말하면 — 불편한 것을 발견한 시민이, 직접 도구를 만들어 고치는 일입니다. 오늘 우리가 할 일이기도 하고요.

2020년에 있었던 일

가짜뉴스 대신 정확한 정보를 알리려고 대학생 한 명이 코로나맵을 만들었습니다. 뒤이어 자원봉사자 80명이 모여 마스크맵을 포함해 10개를 만들었고, 수백만 명이 찾아왔습니다.

지금 달라진 것

그때 여러 명이 며칠씩 붙어 만들던 화면을, 지금은 혼자서 반나절이면 만듭니다. 만드는 일은 이제 어렵지 않습니다.

그래서 오늘 중요한 것

어려운 건 딱 하나 남았습니다. 무엇을 만들지 정확히 말하는 것이요. 그래서 오늘 여러분이 직접 쓸 것은 코드가 아니라 요구사항.md 문서 한 장입니다.

크고 대단한 것 말고, 작지만 끝까지 — 미노베이션(Mini + innovation)

대단한 아이디어보다 끝까지 만들어 본 경험이 남습니다. 작은 변화가 쌓여서 큰 흐름을 만들거든요. 오늘 만들 것은 세상을 바꾸는 서비스가 아니라 웹페이지 한 장입니다. 나만 겪는 불편 같아도 괜찮습니다. 분명 어딘가에 같은 불편을 겪는 사람이 있어요.

만들 것
index.html대문페이지 pre.html발표자료 웹페이지 한 장 + 발표용 슬라이드, 이렇게 두 개
제출할 것
링크 하나구글 폼으로 제출 · 링크가 열려야 제출한 것입니다
말할 것
3분 ~ 5분불편했던 일 → 내가 만든 것 → 배운 것

02. 전체 흐름

문제에서 링크까지, 6단계

단계를 눌러보세요. 무엇을 하고, 무엇을 남기면 되는지 나옵니다. 시간이 넉넉하지 않으니 완벽하게 하지 말고, 다음 단계로 넘어갈 만큼만 하세요.

03. 주제 찾기

자, 여러분 주위에는
어떤 문제가 있나요?

관심 있는 분야를 고르고, 그게 누구의 문제인지도 골라보세요. 나오는 주제들은 정답이 아니라 출발점입니다. 마음에 드는 게 있으면 내 말로 다시 써보세요.

1. 어떤 분야가 궁금한가요? (여러 개 선택 가능)

2. 누구의 문제인가요? (고르면 그 범위의 주제를 먼저 보여드려요)

분야를 하나 이상 골라주세요. 고민될 땐 랜덤으로 하나 뽑기를 눌러보세요.

아무것도 안 떠오를 때 — 이 순서로 넓혀보세요

내가 겪은 불편에서 시작해 조금씩 넓혀갑니다. 어디서 멈춰도 괜찮아요.

나→ 가족→ 이웃→ 지역→ 국가→ 세계

고른 주제, 오늘 안에 될까요?

아래 세 가지만 확인해보세요. 점수가 낮다고 나쁜 주제는 아닙니다. 주제를 바꾸기 전에 더 작게 줄일 수 없는지부터 생각해보세요.

셋 다 10점일 필요는 없어요. 고민되는 주제 2~3개를 하나씩 넣어보고 비교하면 훨씬 빨리 정해집니다.

04. 오늘의 핵심

코드보다 먼저,
요구사항.md 를 씁니다.

집을 지을 때 설계도가 먼저인 것처럼, AI에게 일을 시킬 때도 문서가 먼저입니다. 결과가 마음에 안 들면 코드를 붙잡고 씨름하지 말고 요구사항.md 를 고친 다음 다시 만들어달라고 하세요. 오늘 여러분이 직접 쓰는 문서는 이거 하나뿐입니다.

목적

어떤 문제를, 누구를 위해 푸는지. 여기가 흔들리면 나머지도 전부 흔들립니다.

기능

화면에 무엇이 보이고, 무엇을 누르면 무엇이 바뀌는지. 눈으로 확인할 수 있게 씁니다.

제약

지켜야 할 것과 하지 말 것. 어려우면 템플릿에 적힌 네 줄을 그대로 두세요. 그것만으로 충분합니다.

요구사항.md 템플릿 대괄호 [ ] 안만 내 내용으로 바꾸면 끝. 나머지는 그대로 두세요

05. AI 활용법

    
AI는 심사위원이 아니라,
가장 부지런한 팀원입니다.

    
아래 문장을 그대로 복사해서 쓰세요. [대괄호] 안만 내 주제로 바꾸면 됩니다. 답이 마음에 안 들면 그냥 다시 물어보세요. 그게 핵심입니다.


    


    

      

        
사실인지 직접 확인하기

        
AI는 그럴듯한 거짓말을 합니다. 숫자·법·기관 이름은 꼭 원래 자료에서 다시 확인하세요.

      

      

        
개인정보는 넣지 않기

        
이름·전화번호·주소는 넣지 마세요. 우리가 만든 페이지는 인터넷에서 누구나 볼 수 있습니다.

      

      

        
AI 말을 전부 믿지 않기

        
AI는 많은 사람이 하는 말을 따라 합니다. 그런데 우리가 돕고 싶은 사람은 대개 소수예요.

      

      

        
모르는 코드는 남기지 않기

        
발표 때 "이건 AI가 해줬어요"라고 말하게 됩니다. 모르는 부분은 한 줄씩 물어보고 넘어가세요.

07. 자료실

    
인터넷에 올리기, 그리고 자료 찾기

    
내가 만든 페이지를 인터넷에 올리는 건 GitHub Pages 하나면 끝납니다. 그리고 "이게 문제다"라고 말하려면 근거가 되는 자료가 필요해요. 아래에서 찾아보세요.


    

      
인터넷에 올리는 4단계

      
    
        
  1. GitHub에서 새 저장소(Repository)를 만듭니다. 반드시 공개(Public)로 만들어야 합니다.
    2. 
        
  2. 내가 만든 대문페이지 index.html과 발표자료 pre.html을 저장소에 올립니다. (Add file → Upload files)
    3. 
        
  3. 저장소 위쪽 Settings → Pages로 갑니다. Source는 Deploy from a branch, 브랜치는 main / (root)을 고르고 Save를 누릅니다.
    4. 
        
  4. 1~2분 기다렸다가 https://아이디.github.io/저장소이름/ 에 들어가 보세요. 대문페이지가 열립니다. 발표자료는 주소 끝에 pre.html을 붙이면 됩니다.
    5. 
      

      

        ⚠ 대문페이지 파일 이름은 꼭 index.html 이어야 첫 화면으로 열립니다.
        제출하기 전에 내 휴대폰이나 옆 사람 휴대폰으로 링크를 한 번 열어보세요. 안 열리면 제출하지 않은 것과 같습니다.
      

      

        
          올리는 방법이 기억나지 않는다면 → 위니북스 교안 보기
